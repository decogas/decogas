- **Convención de edición de los `.astro` con CSS/HTML inline**: `admin.astro`,
  `cambios.astro`, `clientes.astro` y `analiticas.astro` guardan su CSS y HTML
  en constantes JS gigantes (`const css = "...";`) donde los saltos de línea
  son el texto literal de 4 caracteres `\r\n` (backslash-r-backslash-n), NO
  saltos de línea reales. La herramienta `Edit` normal falla ahí por el CRLF;
  si además se inserta un salto de línea REAL en vez del texto `\r\n`, el
  build de Astro rompe con "Unterminated string literal" (pasó hoy, se
  detectó y arregló). Para tocar estos bloques: localizar por `indexOf` con
  Node, reconstruir con la secuencia literal `String.fromCharCode(92)+'r'+
  String.fromCharCode(92)+'n'` entre líneas, y **verificar con un build antes
  de dar por bueno el cambio**.
- Cada página admin standalone tiene su propia constante `V` de cache-busting
  (no comparte la `ASSET_V`/`STYLES_V` de `Base.astro`). Subirla en cada
  cambio de esa página o el navegador sirve el JS/CSS viejo.
- El token de acceso de Supabase se genera con el flujo REST de auth
  (`/auth/v1/token?grant_type=password`, admin `dr4389742@gmail.com`) y se
  guarda SIEMPRE en un fichero temporal del scratchpad de la sesión, nunca
